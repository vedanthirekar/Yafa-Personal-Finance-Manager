# Forecasting — diagnosis and plan

**Not worked on in this pass.** Written down so the analysis isn't re-derived
later. Same shape as [`accuracy-notes.md`](accuracy-notes.md): the measurement
exists, the fix is deferred.

## What's running today

`apps/api/app/services/forecasting.py` fits **ARIMA(5,1,0)** on monthly spend
totals, with 80% prediction intervals, a flat mean baseline below 8 months of
history, and per-category z-score anomaly detection.

The order is hardcoded. It was inherited from the 2024 build and, as far as the
git history shows, was never compared against anything.

## The problem: it loses to doing nothing

`uv run python -m ml.eval_forecasting` backtests eight candidates against the
real series in Postgres — expanding window, one-step-ahead, scored by mean
absolute error against a naive "next month looks like last month" baseline.

**demo — 18 months, $7,217/mo average, 10 folds**

| Model | MAE | vs naive |
|---|---|---|
| mean (all history) | $3,093 | **+32.9%** |
| mean (last 3) | $3,786 | +17.9% |
| ARIMA auto (AICc grid) | $3,844 | +16.6% |
| seasonal naive | $3,967 | +14.0% |
| ARIMA(0,1,1) | $4,191 | +9.1% |
| ETS | $4,236 | +8.1% |
| naive (last month) | $4,611 | — |
| **ARIMA(5,1,0) — current** | **$6,684** | **−45.0%** |

**demo_legacy — 75 months, $26,314/mo average, 67 folds**

| Model | MAE | vs naive |
|---|---|---|
| **naive (last month)** | **$15,833** | — |
| ETS | $16,515 | −4.3% |
| ARIMA(0,1,1) | $16,541 | −4.5% |
| mean (last 3) | $16,595 | −4.8% |
| ARIMA auto (AICc grid) | $16,846 | −6.4% |
| **ARIMA(5,1,0) — current** | **$18,448** | **−16.5%** |
| seasonal naive | $20,851 | −31.7% |
| mean (all history) | $23,325 | −47.3% |

The current model is last of eight on one account and sixth of eight on the
other. On the demo account it is 45% *worse* than repeating last month's total.

The intervals say the same thing more quietly. ARIMA(5,1,0)'s 80% band for next
month is `$1,463–$13,881` on demo and `$0–$34,642` on demo_legacy — 1.6x and
5.7x the point forecast respectively. An interval that wide is technically
honest and practically useless.

## Why

1. **Too many parameters for the data.** ARIMA(5,1,0) estimates five
   autoregressive coefficients. Differencing 18 monthly points leaves 17. The
   fit is dominated by whatever noise the recent months happen to contain,
   which is exactly the overfitting signature: worst on the short series
   (−45%), less bad on the long one (−16.5%).
2. **Monthly consumer spend is close to a level plus noise.** That's why the
   flat mean wins on demo and plain naive wins on demo_legacy. There is not
   much autocorrelation for an AR model to find.
3. **Seasonality is weak here.** Seasonal naive beat ARIMA(5,1,0) on demo but
   came second-to-last on demo_legacy, so a December-spike story isn't
   supported. SARIMA is also not fittable on demo at all — seasonal terms at
   m=12 need two full cycles, and there are 18 months.

## Plan, in order

1. **Ship the backtest as the selection mechanism, not a hardcoded order.**
   Score the candidate set per user at request time — it's a handful of fits on
   ≤100 points, milliseconds — and use the winner. Report the chosen model and
   its MAE alongside the forecast.
2. **Report skill, not just a point estimate.** "Within ~$3,100/month, 33%
   better than assuming last month repeats" is a claim that survives being
   questioned. "ARIMA(5,1,0)" is not.
3. **Widen the candidate set only if step 1 shows a gap.** SARIMA once an
   account has ≥24 months; `statsforecast` (AutoARIMA/AutoETS/MSTL) if the
   grid search turns out to be the bottleneck. Note that neither is worth a
   numba + llvmlite dependency while plain naive is still winning.
4. **Keep anomaly detection as-is.** It is unrelated to the forecast model,
   uses per-category z-scores, and has no equivalent problem.

## Caveat on the data

`demo` is generated by `app/services/demo_seed.py`, so its ranking partly
reflects how the seeder draws months. `demo_legacy` is imported from the real
pre-revamp SQLite databases and is the more trustworthy of the two — and it is
the one where *nothing beats naive*, which is the classic result for monthly
household spend.

## Until then

The chart still draws, and `is_fitted` plus the interval width keep it from
overstating itself. But the forecast should not be described as accurate,
because it hasn't been shown to be.
